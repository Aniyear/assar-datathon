## Изменения

- `app.js`: AbortController и отдельный контекст каждой операции. Проверка актуальности
  после fetch, JSON и декодирования изображений; старый ответ/ошибка не меняет новый
  экран даже при повторном job_id. Режим, ключ, файл и демосценарий фиксируются на запуск.
- Смена режима отменяет ожидание и убирает прошлый результат. Деморежим явно помечен,
  выключен при загрузке страницы, не требует настоящего ключа и не вызывает API.
- Некорректный новый файл очищает старый выбор и предпросмотр. Обработаны расширение,
  пустой файл и лимит 100 МиБ. Исправлено повторное всплытие клика файлового input.
- Строгая проверка job_id, статуса, verdict, вложенных объектов, строк, числовых
  таймкодов, порядка событий, количества кадров (1–3), base64 и JPEG. Перед показом
  результата изображения декодируются браузером. Ошибочные таймкоды не становятся нулём.
- `index.html`, `styles.css`: локальный видеоплеер, переходы по таймкодам событий и
  кадров, сообщение о неподдерживаемом кодеке/повреждении файла. Object URL освобождается
  при замене, сбросе и pagehide. Звук по умолчанию выключен.
- Ожидание можно остановить и во время POST. Интерфейс поясняет, что уже принятая
  сервером обработка продолжится. Технические термины убраны из обычных сообщений.
- `tests/browser.html`, `tests/browser.js`, `tests/setup.js`, `tests/serve.py`:
  воспроизводимый браузерный стенд исключительно с синтетическими данными.

Backend, ML, контракт, конфигурация и общие зависимости не изменены.
Новые зависимости не требуются. В production загружаются только index.html, styles.css,
app.js; тестовый setup не подключён к index.html.

## Воспроизведение

Из корня frontend checkout, с установленными общими Python-зависимостями и FFmpeg:

```powershell
node --check app/web/app.js
node --check app/web/tests/browser.js
node --check app/web/tests/setup.js
python -m py_compile app/web/tests/serve.py
python app/web/tests/serve.py --backend-checkout ../integration-cpu --port 8765
```

Открыть `http://127.0.0.1:8765/tests/browser.html` и нажать «Запустить проверки».
Если backend checkout отсутствует, опустить `--backend-checkout`: используется такой
же StaticFiles mount. Стенд слушает только 127.0.0.1, не запускает модель, не является
сервером для сдачи. Остановить Ctrl+C. Синтетический ролик во временной папке удаляется
при завершении; результаты/скриншоты текущего сеанса оставлены в ignored `outputs/ui-tests/`.

Ручная проверка на основном `/`: включить демо, выбрать локальный синтетический MOV,
запустить каждый сценарий, перейти по таймкоду, остановить ожидание, сменить режим,
загрузить другой файл. После перезагрузки демо должно быть выключено.

## Ограничения и следующий шаг

- Системный диалог выбора файла через расширение Edge проверить до конца не удалось:
  расширение требует Allow access to file URLs. Настройки не менялись. Обработчик
  выбора проверен программным синтетическим File в настоящем браузере.
- Нет проверки реального inference, GPU, загрузки в работающий backend, офлайна
  всего сервиса или внешнего URL. Это приёмка frontend, не подтверждение готовности сервиса.
- Ошибка плеера проверена на намеренно невалидном синтетическом media-файле;
  матрица разных неподдерживаемых MOV-кодеков не прогонялась. Реальное воспроизведение
  проверено для синтетического MOV/H.264.
- Если браузер не прочитал длительность видео, диапазон таймкодов обязан подтвердить
  backend по контракту. UI проверяет тип, конечность и неотрицательность всегда.
- Публикация и отправка жюри не выполнялись. Следующий шаг интегратора: принять commit
  frontend в интеграционную ветку и проверить POST→GET на реальном локальном сервисе.

# Зафиксированное разделение данных

17 октября 2026 создан приватный split v1 из технического аудита: 42 файла,
40 различных SHA256. Все 42 исходных файла повторно проверены по размеру и SHA256;
сопоставление меток и отчёт полного декодирования 40 уникальных видео проверены.
Кадры, сцены и содержательные аннотации при этой операции не просматривались.

| Часть | Уникальные видео / группы SHA256 | Файлы с копиями | Положительные | Отрицательные |
|---|---:|---:|---:|---:|
| train | 22 | 22 | 12 | 10 |
| dev | 8 | 9 | 4 | 4 |
| frozen test | 10 | 11 | 5 | 5 |

Классы посчитаны по уникальным SHA256, не по копиям. Известная группа с разными
исходными отметками времени принудительно исключена из test. Сохранены обе
исходные отметки: они не трактуются как исчерпывающая событийная разметка.

Публичная фиксация — [data_split_receipt.json](data_split_receipt.json):
алгоритм `assar-group-stratified-dp-v1`, seed `20261017`, хеш приватного manifest,
отпечатки трёх файлов технического аудита и агрегированные числа.
Идентификаторов, путей, строк меток и ответов закрытой части в квитанции нет.
Приватные файлы находятся только в исключённой из Git папке
`analysis/local/splits/v1/`:

- `frozen.json` — полное неизменяемое распределение, технические метаданные,
  бинарные source labels, исходные отметки; хранит только Анияр/eval.
- `train_dev.csv` — подготовленный список train/dev для ручной разметки и ML;
  строк закрытого test и исходных текстовых меток в нём нет.
- `receipt.json` — копия публичной квитанции.

**Барьер перед настройкой модели:** проверены точные копии по SHA256; похожие
сцены человеком ещё не проверены (`near_duplicate_review: pending`). Поэтому
`model_tuning_allowed: false`, экспорт ML-пакета заблокирован. Этот freeze
защищает от утечки точных копий, но ещё не доказывает независимость похожих сцен.
До снятия барьера не подбирать промпты, пороги, checkpoint, teacher-генерацию или
LoRA; разработка кода и синтетические тесты разрешены. Подтверждать `complete`
можно только после реального локального просмотра человеком.

## Проверка существующего freeze

Из корня репозитория, Python 3.10+; дополнительные зависимости и GPU не нужны:

```powershell
python scripts/data/freeze_split.py validate
python -m unittest discover -s tests/eval -v
```

`validate` проверяет SHA256 публичной квитанции и приватного manifest, фактические
байты каждого исходного файла, исходные отпечатки аудита, покрытие decode-report,
метки/время/пути, размер и баланс частей, группы, защищённую группу, точное
детерминированное восстановление распределения и содержимое train/dev manifest.
В консоль выводятся только агрегаты. Это не новое декодирование и не оценка ML.
При другом расположении данных явно передать `--audit-dir` и `--data-root`:
`--data-root` — корень, относительно которого заданы `relative_path` аудита.

Только для **первоначального** создания новой, ещё не существующей версии:

```powershell
python scripts/data/freeze_split.py freeze --out analysis/local/splits/v1 --receipt docs/data_split_receipt.json
```

Существующие папку freeze и квитанцию команда не заменяет, флага `--force` нет.
Алгоритм сначала объединяет SHA256 и ручные группы транзитивно, распределяет
положительные метки методом наибольших остатков, затем находит точное разбиение
целых групп динамическим программированием. Порядок групп определяется SHA256
от версии алгоритма, seed и group_id. Случайных повторов для получения удобного
test нет. Если группы не укладываются в указанные размеры/баланс, команда
завершается ошибкой; компромисс и новую версию выбирает интегратор явно.

## Локальная проверка похожих сцен

Анияр проверяет все группы для исключения межчастевой похожести и хранит
закрытый test. Омар получает только train/dev для ручной разметки.
Если Омар уже видел или использовал закрытые сцены при выборе модели, сам факт
наличия freeze не возвращает независимость: отметить потерю независимости и
использовать новые разрешённые данные для финальной оценки.

В `analysis/local/manual_groups.json` человек записывает только группы ID,
без описаний сцен. Пример ниже полностью синтетический; не применять его к
реальным данным:

```json
{
  "schema_version": "1",
  "review_status": "complete",
  "groups": [["X-101", "X-102"], ["X-103", "X-104"]]
}
```

`groups: []` с `complete` означает: человек действительно проверил весь набор
на близкие дубликаты и не нашёл дополнительных групп. Это не значение по
умолчанию. Точные SHA256-группы всегда объединяются автоматически. Если группы
известны до первоначального freeze, передать `freeze --groups <локальный JSON>`.
После freeze подтверждение выполняется так:

```powershell
python scripts/data/freeze_split.py review --groups analysis/local/manual_groups.json
```

Команда создаёт отдельный приватный `group_review.json`, связанный с SHA256
исходного freeze; исходные назначения не меняет. Если расширенная группа
пересекает части, команда отклоняет подтверждение. Не перемещать использованный
train/dev в независимый test: интегратор документирует вывод старой версии из
эксплуатации и новую версию до настройки модели либо признаёт test development.
При новом freeze сохранять исходные версии и квитанции; увеличение номера версии
само по себе не устраняет предыдущую утечку. Повторная запись review запрещена.

## Передача Омару

После успешного человеческого review:

```powershell
python scripts/data/freeze_split.py export-train-dev --out analysis/local/ml_package/v1
```

Команда заново проверяет freeze и подтверждение групп, копирует только train/dev
видео и создаёт `train_dev.csv` с относительными путями и `package.json` с хешами.
Расширенные group_id сохраняются в ML-manifest. Полные `open_labels.xlsx`,
`labels_normalized.csv`, `frozen.json`, test-видео и test-метки в пакет не входят.
Передать пакет Омару только между контролируемыми машинами команды, без Git,
облачного AI и внешней телеметрии. `train_dev.csv` из freeze до review служит
только перечнем для ручной проверки; пакет для настройки создаётся после review.

Омар использует train для обучения, dev для выбора модели и параметров;
закрытый test остаётся у Анияра до model freeze. Runtime/inference не получает
CSV и не читает ID, имя файла, истинную метку или эталонный таймкод как признаки.
Все кадры, crops, перекодированные копии и производные клипы наследуют group_id
и split исходного ролика: создавать их внутри соответствующей части, сохранять
parent SHA256 в локальном manifest производных. Нельзя повторно распределять
производные по их новому SHA256; скрипт замораживает исходники и не сканирует
созданные позже производные. При отсутствии parent SHA256 производный материал
не допускать к train/dev/test до восстановления происхождения.

С десятью уникальными test-видео итоговые метрики будут нестабильны. Баланс
бинарных меток не означает баланс типов событий или подтверждение нормативов.
Тесты скрипта используют исключительно синтетические байты/метки; фактическая
точность модели, новые ракурсы и скорость inference здесь не измерялись.

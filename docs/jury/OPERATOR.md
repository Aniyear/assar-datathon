## Только после отдельного разрешения публикации

Подготовлена явная команда будущей публикации. **В этом задании она не выполнялась.**
Без `--publish` production-ngrok отклоняется; с ним штатный preflight и readiness
всё равно обязательны. Туннель создаётся только после startup API и принадлежит
его launcher, inspector отключён, вывод фильтруется. Тестовая страница не подменяет API.

Сначала штатно остановить локальный запуск: две копии сервиса одновременно не нужны.
Затем, только после разрешения публикации:

```powershell
& .\scripts\assar.ps1 start --mode production --port 8000 `
  --model-config .\outputs\service\production\model.local.json `
  --ngrok .\outputs\tools\ngrok\ngrok.exe --publish
```

Закреплённый ngrok 3.39.11 уже установлен на машине Анияра. Launcher использует
ранее настроенную официальную авторизацию и создаёт отдельный защищённый профиль
без вывода токена. Если профиль отсутствует — выполнить официальный add-authtoken
локально по [инструкции настройки](../NGROK_TEST.md), не присылать токен в чат.
Существующий network-test при этом не считается опубликованным production.
CPU-проверки подтверждают явное разрешение и отказ при неготовности; реальный
production-туннель и внешний API остаются **not run**.

После разрешённого подключения проверить **с другой сети** на синтетическом MOV:
UI и API по одному HTTPS origin; 401 без/с неверным ключом; 202 с верным ключом;
polling до допустимого terminal результата; отсутствие HTML-заглушки вместо JSON;
повторный GET; отсутствие ключей/содержимого в журналах. Синтетический failed не
подтверждает реальный done. Дообучение или оценка на видео жюри запрещены.

Не открывать напрямую localhost llama-server. Не использовать нескольких GPU/API
workers. Проверить питание, отсутствие сна, доступность сети и отсутствие чужого
ML-прогона. Указать жюри фактическое окно доступности в UTC+5, не обещать 24/7.

## Остановка и сбой

Для штатного сервиса: Ctrl+C в его окне или в другом PowerShell
`& .\scripts\assar.ps1 stop`. Затем status; убедиться, что собственные worker/server
завершены. В варианте с `--publish` тот же launcher закрывает собственный туннель;
проверить `tunnel_cleanup_confirmed` в локальной квитанции. Не kill-ить чужие PID и не запускать
вторую копию для обхода занятого слота. Сохранить SQLite/квитанции только локально.

При сбое дать жюри технический статус и job_id; не пересылать содержимое ответа
модели сторонним сервисам. Ключ менять только согласованно с проверяющими.

проверкой каждого обнаруженного события. Два FN получены после завершённых

terminal JSON; чтение исходного локального файла до отправки в него не включено.
Время ожидания готовности после recovery не называется временем обработки job.

показатель**, **1164 MiB после остановки**. Интервал — 1 s плюс длительность вызова
nvidia-smi. Это не непрерывное пиковое измерение и не память только нашего процесса;
в число входит рабочий стол. Гарантия отсутствия кратких больших пиков не получена.

Readiness: `status=acceptance_failed`. Три узких validation-флага установлены по
фактам: хеши весов проверены на этом хосте, GPU 3060 измерен, analyze_video реализован

с локально разрешёнными путями проверен: SHA256 проходит, единственная причина
отказа — status не `ready`; GPU не запускался. Production не опубликован.

## Оставшиеся блокеры и адресные задания

1. **Омар / ML и качество:** два FN на основном dev (TP=1 из 3 положительных).
   Локально разобрать, где причина в распознавании, условиях или ограниченном
   покрытии двух правил. Не выдавать эти результаты за качество всего кейса,
   не расширять нормативное покрытие без подтверждения. Полные локальные входы и
   следы привязаны в `private-selection.json` / `private-metadata.jsonl`; наружу
   передавать только агрегаты. Метод оценки и следующую модель определяет Омар.
2. **Омар / ML-кандидаты:** диагностический кандидат содержит только два различных
   кадра обязательной перепроверки. Проверка каталога требует три; безопасный итог
   сейчас `failed`, не ложный отрицательный. Синтетический воспроизводитель:
   `tests/integration/test_mandatory_budget.py::test_three_frame_verification_is_not_claimed_for_two_frame_candidate`.
   Для положительного результата требуется реальное достаточное основание,
   а не повтор одного кадра, снятие guard или ослабление каталога.
3. **Интегратор после точного исправленного handoff:** повторить затронутые CPU-
   регрессии и обоснованную часть реальной приёмки на свободной GPU. Не переписывать
   эту квитанцию, создать новую. Только по результатам решать readiness.
4. **Капитан / выпуск:** содержание фактов и применимость оговорок на реальных
   доказательствах требуют локальной человеческой проверки. На frozen test в этом
   задании не измерялось. Публикация production и отправка URL/ключа жюри не выполнены.

VFR/edit-list, неизвестные роли, содержимое сумки, дискретная выборка 1 s и
невозможность доказать полноту всех юридических предпосылок остаются ограничениями.
Ни успешный HTTP, ни TP по бинарной метке их не устраняют.

## Точная команда штатного запуска

Сейчас она **штатно откажет** до закрытия приёмки; готовность ради запуска не
подменяется. Локальный файл с фактическими абсолютными путями уже подготовлен:
`outputs/service/production/model.local.json`. Он не содержит ключа и не входит в Git.

```powershell
Set-Location 'C:\Users\aniya\Рабочий стол\assar-datathon\.worktrees\integration-cpu'
& .\scripts\assar.ps1 check --model-config .\outputs\service\production\model.local.json
& .\scripts\assar.ps1 start --model-config .\outputs\service\production\model.local.json --port 8000
# В другом PowerShell или Ctrl+C в окне сервиса:
& .\scripts\assar.ps1 stop
```

После принятого исправления регенерировать этот локальный конфиг из нового
`configs/model.yaml`, сохранив абсолютные пути к уже проверенным артефактам:

```powershell
@'
import json
from pathlib import Path
cfg = json.loads(Path('configs/model.yaml').read_text(encoding='utf-8'))
for section, field, root in [('weights', 'path', '../ml-2b4b-experiment'),
                            ('mmproj', 'path', '../ml-2b4b-experiment'),
                            ('runtime', 'server_bin', '../ml-portability-3060')]:
    cfg[section][field] = str((Path(root) / cfg[section][field]).resolve(strict=True))
p = Path('outputs/service/production/model.local.json')
p.parent.mkdir(parents=True, exist_ok=True)
p.write_text(json.dumps(cfg, ensure_ascii=False, indent=2), encoding='utf-8')
'@ | & '..\..\.venv\Scripts\python.exe' -
```

Не заменять status/флаги вручную в этой команде. При разрешённом запуске frontend
и API доступны на `http://127.0.0.1:8000`; локальный API-ключ создаёт штатный launcher
в `outputs/service/production/private/api-key.txt` с ограниченным ACL. Не печатать
его в логи/чат, не коммитить. Один API worker, без `--reload`.
Публикация ngrok — отдельное действие по [SERVICE_OPERATIONS.md](SERVICE_OPERATIONS.md),
в текущем прогоне внешний доступ с банковскими данными не открывался.
